# 開始・終了ノードとノード順序の導入

## 概要

アンケート調査票のデータ構造として適切なフローチャートを作成するため、以下の機能を導入する：

1. **開始ノード・終了ノード**: フローの開始点と終了点を明示
2. **ノード順序**: 循環フローを防止し、一方向の設問フローを保証

## 現状の問題

### 問題1: 循環フローが容易に作成できる

- ノードに順序の概念がないため、Q3 → Q1 のような逆方向のエッジも作成可能
- アンケート調査票では設問は一方向に進むため、循環は論理的に不正

### 問題2: 設問終了 vs 到達ルール未設定の区別ができない

- 出力エッジがないノードが「終了ノード」なのか「設定漏れ」なのか判別不能
- 網羅性チェックで警告が出ても、意図的な終了点との区別ができない

---

## 検討した案

### 問題1（循環フロー防止）の候補

| 案 | 概要 | メリット | デメリット |
|---|------|---------|-----------|
| A. ノードに順序番号を追加 | 各ノードに `order: number` を持たせ、順序が小さいノードから大きいノードへのエッジのみ許可 | シンプル、直感的 | 順序の管理が必要、ノード追加時に順序調整が発生 |
| B. 到達ルール設定時に循環チェック | エッジ追加時にDFSで循環を検出し、警告または禁止 | 既存のデータモデルを変更不要 | 検出のみで根本解決にならない可能性 |
| C. 開始ノード・終了ノードを明示 | 特別なノードタイプとして「開始」「終了」を導入し、有向非循環グラフ（DAG）を強制 | 構造が明確になる | データモデルの変更が必要 |
| **D. 配列インデックスを順序として使用** | nodes 配列の順番をそのまま順序として扱う | データモデル変更が最小限、配列操作で順序変更が容易 | 配列操作時に注意が必要 |

### 問題2（終了点の明示）の候補

| 案 | 概要 | メリット | デメリット |
|---|------|---------|-----------|
| A. 終了ノードタイプを追加 | 専用の終了ノードを作成 | 明示的で分かりやすい | すべての終点に終了ノードを配置する手間 |
| B. ノードに「終了フラグ」を追加 | `isTerminal: boolean` フラグを追加し、意図的な終了点を明示 | 既存ノードに追加するだけ | フラグ管理の手間 |
| C. 出力エッジがないノードを自動検出して確認を促す | 終了点候補をUIでハイライトし、ユーザーに確認を求める | 実装が軽量 | 根本解決にならない |

### 採用する案

**問題1**: 案D（配列インデックスを順序として使用）+ 案B（到達ルール設定時のチェック）
**問題2**: 案A（開始ノード・終了ノードの導入）+ ラベル固定

## 実装方針

### Phase 1: 開始ノード・終了ノードの導入

#### 1.1 データモデルの変更

**`src/types/flowchart.ts`**

```typescript
/** ノードタイプ（設問タイプとは別に、フロー上の役割を定義） */
export type NodeType = 'start' | 'question' | 'end';

/** フローチャートのノード */
export interface FlowchartNode {
  id: string;
  label: string;
  shape?: NodeShape;
  className?: string;
  /** ノードタイプ（デフォルト: 'question'） */
  nodeType?: NodeType;
  /** 設問カテゴリ（nodeType が 'question' の場合のみ有効） */
  questionCategory?: QuestionCategory;
  /** 選択肢（SA/MAの場合） */
  choices?: ChoiceOption[];
  /** このノードが表示される経路を表すルール */
  entryRules?: NodeEntryRule[];
}

/** カスタムノード（エディタ用） */
export interface CustomNode {
  id: string;
  label: string;
  shape: NodeShape;
  /** ノードタイプ（デフォルト: 'question'） */
  nodeType?: NodeType;
  questionCategory?: QuestionCategory;
  choices?: ChoiceOption[];
  entryRules?: NodeEntryRule[];
}
```

**注意**: `order` フィールドは追加しない。代わりに `nodes` 配列のインデックスを順序として使用する。

#### 1.2 開始ノードの仕様

| 項目 | 仕様 |
|------|------|
| ノードタイプ | `nodeType: 'start'` |
| 形状 | 台形（`shape: 'trapezoid'`） |
| ラベル | **「開始」固定（編集不可）** |
| 入力エッジ | 不可（entryRules は空） |
| 出力エッジ | 必須（1つ以上） |
| 設問カテゴリ | なし（`questionCategory` は未設定） |
| 数量制限 | フローチャート内に1つのみ |
| 配列位置 | **常に配列の先頭（index: 0）** |
| 初期状態 | **初期表示時に1つ存在** |
| 追加 | **不可（常に1つ存在するため）** |
| 削除 | **不可** |

#### 1.3 終了ノードの仕様

| 項目 | 仕様 |
|------|------|
| ノードタイプ | `nodeType: 'end'` |
| 形状 | 逆台形（`shape: 'trapezoidAlt'`） |
| ラベル | **「終了」固定（編集不可）** |
| 入力エッジ | 必須（1つ以上） |
| 出力エッジ | 不可（他ノードの entryRules から参照されない） |
| 設問カテゴリ | なし |
| 数量制限 | 複数可（異なる終了点を表現） |
| 配列位置 | **常に配列の末尾** |
| 初期状態 | **初期表示時に1つ存在** |
| 追加 | **可能（複数の終了点を表現）** |
| 削除 | **可能（ただし最低1つは残す必要あり）** |

#### 1.4 ラベル固定の実装

開始・終了ノードのラベルは固定とし、ユーザーによる編集を不可とする。

```typescript
// ノードタイプに応じてラベルを取得
const getNodeLabel = (node: CustomNode): string => {
  if (node.nodeType === 'start') return '開始';
  if (node.nodeType === 'end') return '終了';
  return node.label;
};

// Mermaid コード生成時
const label = node.nodeType === 'start' ? '開始'
            : node.nodeType === 'end' ? '終了'
            : node.label;
```

#### 1.5 初期状態

フローチャートの初期状態には、開始ノードと終了ノードが1つずつ存在する。

```typescript
// 初期データ
const initialNodes: CustomNode[] = [
  { id: 'start', nodeType: 'start', label: '開始', shape: 'trapezoid' },
  { id: 'end', nodeType: 'end', label: '終了', shape: 'trapezoidAlt' },
];
```

#### 1.6 UI の変更

**ノード追加ボタン**:
- 「終了ノード追加」ボタン（複数追加可能）
- 「設問ノード追加」ボタン（既存の「ノード追加」）
- ~~「開始ノード追加」ボタン~~ → **不要**（初期状態で存在し、削除不可のため）

**ノード削除**:
- 開始ノード: 削除不可（削除ボタンを非表示または非活性）
- 終了ノード: 最後の1つは削除不可（削除ボタンを非活性）
- 設問ノード: 自由に削除可能

**ノード編集ダイアログ**:
- 開始ノード: ラベル表示のみ（「開始」固定）、設問カテゴリ・選択肢は非表示
- 終了ノード: ラベル表示のみ（「終了」固定）、設問カテゴリ・選択肢は非表示
- 設問ノード: 既存の編集機能（ラベル編集可能）

**到達ルール編集**:
- 開始ノードを接続先として選択不可
- 終了ノードを接続元として選択不可

#### 1.7 バリデーション

| チェック項目 | エラーメッセージ |
|-------------|-----------------|
| 開始ノードから出力エッジがない | 「開始ノードから少なくとも1つのエッジを設定してください」 |
| 終了ノードに入力エッジがない | 「終了ノードへの到達ルールを設定してください」 |
| 終了ノードに到達しない経路がある | 「すべての経路が終了ノードに到達する必要があります」 |

**注意**: 以下のチェックは初期状態とUI制約により不要：
- 開始ノードの存在チェック（初期状態で存在、削除不可）
- 開始ノードの複数存在チェック（追加不可）
- 開始ノードへの入力エッジチェック（UIで接続先として選択不可）
- 終了ノードからの出力エッジチェック（UIで接続元として選択不可）

### Phase 2: ノード順序の導入（配列インデックスベース）

#### 2.1 順序の定義

`order` フィールドを追加せず、`nodes` 配列のインデックスをそのまま順序として使用する。

```typescript
// 順序の取得
const getNodeOrder = (nodes: CustomNode[], nodeId: string): number => {
  return nodes.findIndex(n => n.id === nodeId);
};

// 順序チェック
const isValidEdgeOrder = (
  nodes: CustomNode[],
  sourceNodeId: string,
  targetNodeId: string
): boolean => {
  const sourceIndex = nodes.findIndex(n => n.id === sourceNodeId);
  const targetIndex = nodes.findIndex(n => n.id === targetNodeId);
  return sourceIndex < targetIndex;
};
```

#### 2.2 配列の順序規則

| 位置 | ノードタイプ | 説明 |
|------|------------|------|
| index: 0 | 開始ノード | 常に配列の先頭 |
| index: 1 ~ n-2 | 設問ノード | 設問の順番に配置 |
| index: n-1 ~ | 終了ノード | 常に配列の末尾 |

```typescript
// 配列構造の例
const nodes: CustomNode[] = [
  { id: 'start', nodeType: 'start', ... },   // index: 0（開始）
  { id: 'q1', nodeType: 'question', ... },   // index: 1（設問1）
  { id: 'q2', nodeType: 'question', ... },   // index: 2（設問2）
  { id: 'q3', nodeType: 'question', ... },   // index: 3（設問3）
  { id: 'end1', nodeType: 'end', ... },      // index: 4（終了1）
  { id: 'end2', nodeType: 'end', ... },      // index: 5（終了2）
];
```

#### 2.3 循環防止ルール

到達ルール（エッジ）設定時に以下のルールを適用：

```
接続元ノードの配列インデックス < 接続先ノードの配列インデックス
```

- 同じインデックス同士の接続は**不可**（自己ループ防止）
- インデックスが大きいノードから小さいノードへの接続は**不可**（逆方向防止）

#### 2.4 ノード追加時の配列操作

```typescript
// 終了ノード追加（常に末尾）
const addEndNode = (nodes: CustomNode[], newNode: CustomNode): CustomNode[] => {
  return [...nodes, newNode];
};

// 設問ノード追加（終了ノードの前）
const addQuestionNode = (nodes: CustomNode[], newNode: CustomNode): CustomNode[] => {
  const endNodes = nodes.filter(n => n.nodeType === 'end');
  const otherNodes = nodes.filter(n => n.nodeType !== 'end');
  return [...otherNodes, newNode, ...endNodes];
};
```

**注意**: 開始ノードは初期状態で存在し、追加不可のため `addStartNode` 関数は不要。

#### 2.5 UI の変更

**ノード一覧（サイドバー）**:
- ノードを配列順（インデックス順）に表示
- ドラッグ＆ドロップで順序変更（将来の拡張）

**到達ルール編集**:
- 接続元ノードの選択肢から、インデックスが接続先以上のノードを除外
- 開始ノード（index: 0）は常に選択可能な接続元
- 終了ノードは接続元として選択不可

#### 2.6 順序変更時の処理

ノードの順序（配列位置）を変更した場合：

1. 配列内でノードを移動（splice 操作）
2. 開始ノードは先頭、終了ノードは末尾の制約を維持
3. 順序違反のエッジを検出
4. 違反エッジを警告表示またはハイライト
5. ユーザーに修正を促す（自動削除はしない）

#### 2.7 バリデーション

| チェック項目 | エラーメッセージ |
|-------------|-----------------|
| 順序違反のエッジが存在 | 「{sourceNode} → {targetNode} は順序に違反しています」 |
| 開始ノードが先頭でない | 「開始ノードは配列の先頭に配置してください」 |
| 終了ノードが末尾でない | 「終了ノードは配列の末尾に配置してください」 |

### Phase 3: UI の改善（将来の拡張）

#### 3.1 ドラッグ＆ドロップによる順序変更

- サイドバーのノード一覧でドラッグ＆ドロップ
- 開始ノードは移動不可（常に先頭固定）
- 終了ノードは終了ノード同士でのみ順序変更可能
- 順序変更後に違反エッジを検出・警告

#### 3.2 フローチャートの自動レイアウト

- 配列インデックスに基づいて左から右（または上から下）に自動配置
- 同じ階層のノードは縦に並べる

#### 3.3 到達経路の可視化

- 特定のノードを選択すると、そのノードへの到達経路をハイライト
- 終了ノードに到達しない経路を警告色で表示

## テストケース

### Phase 1 のテストケース

#### テストケース 1.1: 初期状態

```
初期状態: [開始] [終了]
配列: [開始, 終了]
```

- 初期表示時に開始ノードと終了ノードが1つずつ存在すること
- 開始ノードが配列の先頭（index: 0）にあること
- 終了ノードが配列の末尾にあること

#### テストケース 1.2: 開始ノードの基本動作

```
[開始] → Q1 → Q2 → [終了]
配列: [開始, Q1, Q2, 終了]
```

- 開始ノードが1つ存在すること
- 開始ノードに入力エッジがないこと
- 開始ノードから出力エッジがあること
- 開始ノードのラベルが「開始」固定であること
- 開始ノードが削除不可であること

#### テストケース 1.3: 複数の終了ノード

```
[開始] → Q1 ─┬─ [選択肢A] → Q2 → [終了1]
             └─ [選択肢B] → [終了2]
配列: [開始, Q1, Q2, 終了1, 終了2]
```

- 複数の終了ノードが存在可能なこと
- すべての終了ノードが配列の末尾にあること
- すべての経路が終了ノードに到達すること
- 終了ノードのラベルが「終了」固定であること
- 終了ノードが2つ以上ある場合は削除可能なこと
- 最後の1つの終了ノードは削除不可であること

#### テストケース 1.4: 開始ノードへの接続禁止

- 到達ルール編集で、接続先に開始ノードが表示されないこと

#### テストケース 1.5: 終了ノードからの接続禁止

- 到達ルール編集で、接続元に終了ノードが表示されないこと

#### テストケース 1.6: ラベル編集の制限

- 開始ノードをクリックしてもラベル編集フィールドが表示されないこと
- 終了ノードをクリックしてもラベル編集フィールドが表示されないこと
- 設問ノードはラベル編集が可能なこと

### Phase 2 のテストケース

#### テストケース 2.1: 順序に基づくエッジ制約

```
配列: [開始(0), Q1(1), Q2(2), 終了(3)]
```

- Q2 → Q1 のエッジが作成不可であること（index 2 → 1）
- Q1 → Q2 のエッジが作成可能であること（index 1 → 2）

#### テストケース 2.2: 設問ノード追加時の配列位置

```
初期: [開始, Q1, 終了]
Q2追加後: [開始, Q1, Q2, 終了]
```

- 新規設問ノードが終了ノードの前に挿入されること

#### テストケース 2.3: 終了ノード追加時の配列位置

```
初期: [開始, Q1, 終了1]
終了2追加後: [開始, Q1, 終了1, 終了2]
```

- 新規終了ノードが配列の末尾に追加されること
